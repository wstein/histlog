= Runtime View
:page-layout: default

The important runtime flows are append-only session capture, consolidation, import, verification, and query.
Each flow runs as a short-lived CLI invocation; histlog does not run a daemon or resident OTP service.

== Session Capture

`Histlog.SessionWriter` creates a live session file, writes `session_started`, interns commands and folders, appends `execution_observed` events, and moves the file to `closed/` after `session_ended`.

== Shell Hook State

`Histlog.Hook` persists small JSON files under `hook-state/` so separate shell hook invocations can recover the current writer state.
These files are ephemeral adapter state, not canonical history.
They may be deleted, repaired, or recreated without changing the historical record.

The canonical boundary remains the session NDJSON file:

* `hook-state/*.json` stores disposable runtime adapter state.
* `sessions/**/*.ndjson` stores immutable shell history events.

== Consolidation

`Histlog.Consolidator` scans closed sessions for a date, validates NDJSON and sequence numbers, quarantines malformed files, and writes sessions, execution rows, and processed-session checkpoints to `$HISTLOG_ROOT/histlog.db` inside one SQLite transaction.
It is invoked explicitly by `histlog consolidate` or by an external scheduler that runs the CLI.

== Verification

`Histlog.Verifier` opens `histlog.db`, checks the schema version and required tables, and compares processed-session checkpoint counts with materialized execution rows.

== Import

`Histlog.Import` parses zsh, bash, fish, or native NDJSON inputs into `import_batch_*` and `imported_execution` events.

== Query

`Histlog.Query` reads consolidated SQLite rows and merges them with live session NDJSON so the current shell is visible before consolidation.
