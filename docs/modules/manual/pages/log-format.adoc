= Log Format
:page-layout: default

histlog stores canonical history internally as compact NDJSON.
This page documents the on-disk truth for debugging, verification, and tooling work.
The public query command does not expose NDJSON; use `histlog export --format ndjson` for line-oriented export.

== Session File Example

[source,json]
----
{"event":"session_started","host":"Mac","process_id":80615,"parent_process_id":0,"schema_version":1,"seq":1,"session_id":"XBQxaBoA6-rWLbEKJqoAIw","shell":"fish","timestamp":"2026-05-06T21:42:54.828788Z"}
{"command":"mix test","command_id":1,"event":"command_defined","is_private":0,"schema_version":1,"seq":2,"timestamp":"2026-05-06T21:43:07.251237Z"}
{"event":"folder_defined","folder":"/repo","folder_id":1,"schema_version":1,"seq":3,"timestamp":"2026-05-06T21:43:07.252000Z"}
{"command_id":1,"completeness":"complete","cwd_id":1,"duration_ms":331,"event":"execution_observed","exec_id":1,"exit_status":0,"schema_version":1,"seq":4,"timestamp":"2026-05-06T21:43:06.769Z"}
{"event":"session_ended","schema_version":1,"seq":5,"timestamp":"2026-05-06T21:45:00Z"}
----

Session files store the `session_id` only in `session_started`.
Later records rely on the file boundary and sequence number.
Command text is normalized by trimming leading and trailing whitespace before persistence.
Commands that originally started with a space are tracked with `is_private` on `command_defined` instead of preserving that leading space in the command text.

== Derived Query Row

[source,json]
----
{"event":"execution","session_id":"XBQxaBoA6-rWLbEKJqoAIw","exec_id":1,"command":"mix test","cwd":"/repo","timestamp":"2026-05-06T21:43:06.769Z","duration_ms":331,"exit_status":0,"completeness":"complete","is_private":0,"shell":"fish","host":"Mac"}
----

Derived query rows are materialized views, not canonical truth.
Inside `histlog.db`, command text, paths, command argument path facts, shells, sessions, imports, and command occurrences are stored in separate relational tables.
Use `history_view` as the preferred database read surface for command history.

== Derived Command Paths

[source,sql]
----
SELECT command_id, arg_position, path, type, path_exists, source
FROM command_paths_view;
----

Command path rows are derived analysis facts.
They are rebuilt from command text and cwd during consolidation or import materialization.
They are not canonical history.
The base `command_paths` table stores only relationship facts; command text already contains the original argument text, and `paths` owns the normalized path string.
`path_exists` is a command-time analysis fact: it records whether the analyzer believed the argument resolved to an existing filesystem path when that command was materialized.
It is intentionally separate from `paths.type`, which is the normalized path dimension's current known type and may be upgraded by later observations.

== Partial Execution

[source,json]
----
{"command_id":1,"completeness":"partial","cwd_id":1,"duration_ms":null,"event":"execution_observed","exec_id":2,"exit_status":null,"schema_version":1,"seq":6,"timestamp":"2026-05-06T21:44:00Z"}
----

Partial executions are valid because shell hooks can miss completion data.

== Database Checkpoint

[source,sql]
----
SELECT session_file, session_uid, date, events_count, commands_count
FROM processed_sessions
WHERE date = '2026-05-06';
----

`histlog.db` stores a normalized command projection plus processed-session checkpoints.
Closed session NDJSON remains the canonical source; the database is rebuilt from those files when needed.
Use `sessions_view` as the preferred database read surface for session summaries.

== Redacted Command

[source,json]
----
{"command":"deploy token=[REDACTED]","command_id":1,"event":"command_defined","redacted":true,"schema_version":1,"seq":2,"timestamp":"2026-05-06T21:43:07Z"}
----

Redaction happens before persistence.
