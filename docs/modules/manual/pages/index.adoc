= Manual
:page-layout: default

histlog stores shell history as append-only NDJSON event streams and daily materialized files.

== Command Reference

The Elixir app exposes an escript entrypoint.

[source,sh]
----
cd app
mix escript.build
./histlog consolidate --root /tmp/histlog --date 2026-05-06
./histlog consolidate --root /tmp/histlog --date 2026-05-06 --rebuild
./histlog verify --root /tmp/histlog --date 2026-05-06
./histlog query --root /tmp/histlog --date 2026-05-06 --command mix
./histlog query --root /tmp/histlog --date 2026-05-06 --command mix --format ndjson
./histlog tail --root /tmp/histlog --date 2026-05-06 --count 10
./histlog import test/fixtures/import/zsh_history --root /tmp/histlog --date 2026-05-06 --source zsh_history
./histlog doctor zsh
----

From the repository root, `make build` compiles the application and rebuilds `app/histlog`.
Use `make install` to symlink `${PREFIX:-$HOME/.local}/bin/histlog` to the repo-built `app/histlog`.
That local-development install keeps interactive shells on the latest rebuilt escript without a daemon.

== Shell Integration

histlog does not edit shell rc files.
Print the integration code and opt in explicitly:

[source,sh]
----
eval "$(histlog init zsh)"
eval "$(histlog init bash)"
histlog init fish | source
eval "$(histlog init zsh --binary /absolute/path/to/histlog)"
eval "$(histlog init zsh --durability balanced)"
----

`histlog init` auto-detects the shell from `HISTLOG_SHELL`, `SHELL`, and then parent process name.
Pass the shell explicitly when writing setup files.
Use `--binary` when setup should pin an exact histlog executable instead of relying on PATH lookup.
Durability modes are `safe`, `balanced`, and `fast`; `balanced` is the default.
The automated smoke suite sources generated zsh, bash, and fish snippets in real shell subprocesses when those shells are available.

Completion scripts can also be printed directly:

[source,sh]
----
histlog completions zsh
histlog completions bash
histlog completions fish
----

`consolidate` reads closed sessions for the selected day, writes daily materialized files, and emits the manifest as JSON.
`consolidate --rebuild` ignores the existing checkpoint for that date and rewrites daily materializations from current closed sessions.
`verify` recomputes daily materialization record counts and checksums, then compares them to the manifest.
`query` prints a human-readable execution table by default, using derived execution rows from daily materializations and currently live sessions.
Use `query --format ndjson` for one JSON object per line when scripting.
`tail` prints the latest canonical daily and live session events.
`import` parses zsh, bash, fish, or native NDJSON history and stores synthetic import events under `imports/`.
`doctor` prints JSON diagnostics for the selected shell integration.
